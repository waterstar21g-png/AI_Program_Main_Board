6. 추가로 발견한 원인 (코드 재검토 결과):
`run_save_submit_and_verify` 맨 앞에서 `save_modal_visible(page)`가
False면 **저장하기 버튼을 찾아보지도, 클릭을 시도하지도 않고** 바로
RuntimeError를 던지는 하드 게이트가 있었음.

그런데 `save_modal_visible()`은 저장하기 텍스트를 `^저장하기$` 정확매치로만
판정했음 — 실제 사이트 버튼에 아이콘·공백(전각공백 등)이 섞여 있으면
이 정확매치가 실패해 모달이 열려 있는데도 "닫혀 있다"고 오판, 그대로
클릭 시도 자체를 건너뛰고 실패 처리됨. 클릭에 쓰는 실제 탐색 함수
(`_find_footer_save_by_cancel_pair`, `resolve_save_submit_control`)는
훨씬 관대한데, 사전 게이트만 더 엄격해서 서로 어긋난 것.
