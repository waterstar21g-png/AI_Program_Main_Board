## 원인 분석 (참고)

### 1. P2 가 "다른 크롬"을 띄우는 이유

`P2/collect.py` 의 `PROFILE_DIR = P2/.chrome-profile` — 평소 쓰는 Chrome 과 완전히
별개인 전용 프로필로 Chrome 을 새로 띄운다 (v2.0.4, 2026-08-07 부터).
Chrome 136 부터 `--remote-debugging-port` 가 기본 사용자 데이터 디렉터리에서
무시되므로, 비표준 `--user-data-dir` 이 필수라 선택의 여지가 없다.
그 결과 북마크·로그인 세션·확장이 전부 별개다.

### 2. 그 프로필에 확장이 없던 이유 (두 겹)

| # | 원인 | 근거 |
|---|------|------|
| a | Chrome 137 부터 정품 Chrome 에서 `--load-extension` 스위치 제거 | 크롬 로그 `--load-extension is not allowed in Google Chrome, ignoring.` |
| b | `--disable-extensions-except=<로컬경로>` 가 "지정 경로 외 전부 비활성화" | 웹스토어로 설치해 둔 더망고 확장까지 매 실행 꺼버림 |

(a) 때문에 동봉한 로컬 확장이 안 붙고, (b) 때문에 웹스토어 설치분도 꺼지므로
결과적으로 활성 확장 0개 → "더망고 확장프로그램이 설치되어 있지 않습니다" 배너.
두 인자 모두 v2.0.19 (`53a3bdc`, 2026-08-08) 에서 함께 들어왔다.

### 3. v2.1.50 이 듣지 않았던 이유

`--enable-unsafe-extension-debugging` 만 추가하고 `--remote-debugging-port` 를
유지했다. 이 플래그는 `--load-extension` 을 되살리는 것이 아니라 CDP
`Extensions.loadUnpacked` / BiDi `webExtension.install` 을 여는 용도이며,
크롬 공식 안내상 `--remote-debugging-pipe` 와 함께 써야만 동작한다
(포트로 붙으면 `Method not available.`). 그래서 롤백 전후 에러가 동일했다.

### 4. 메뉴 차이

확장의 `inject.js` · `func.js` · `load.js` 를 확인했으나 관리자 상단 메뉴를
생성·변경하는 코드는 없다. 두 창은 URL 부터 다르고(`admin_config.php` vs
`admin.php`) 프로필이 달라 로그인 세션도 별개다. 확장 설치 여부와는 별개 사안.
