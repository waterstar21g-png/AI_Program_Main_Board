6. 반영 내용
- 원인: run.ps1이 버전이 바뀔 때마다 .next/.next-dev 캐시를 자동으로
  전부 삭제했음. 이번 세션 중 2.4.0→2.4.1→2.4.2로 짧은 시간에 여러 번
  버전을 올리면서 매번 강제 콜드 컴파일이 발생 — Windows에서는 백신
  실시간 검사까지 겹쳐 콜드 컴파일이 수 분씩 걸릴 수 있고, 이게
  "교착상태"처럼 보였을 것으로 판단(실제로는 진행 중이었을 가능성 높음)
- 수정: 버전이 바뀌어도 더 이상 자동으로 캐시를 지우지 않음 (webpack
  자체 캐시가 파일 변경분만 알아서 다시 컴파일함). 캐시가 깨진 것 같을
  때만 수동으로 `.\run.ps1 -Clean` 실행하도록 옵션화
- npm run dev 시작 직전에 "첫 컴파일은 오래 걸릴 수 있다 / 작업관리자로
  node.exe CPU 확인 / '✓ Compiled' 뜨면 끝" 안내 문구 추가
- 이번 2.4.2→2.4.3 전환 1회는 옛 run.ps1 로직 때문에 어쩔 수 없이
  마지막 콜드 컴파일이 발생하지만, 이후부터는 버전이 바뀌어도 캐시 유지
