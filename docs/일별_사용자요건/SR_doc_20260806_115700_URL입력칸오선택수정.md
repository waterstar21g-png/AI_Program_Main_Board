6. 반영 내용
- 원인: url_input() 선택자가 "버튼을 포함하는 tr/table/div 중 마지막"이라는
  느슨한 기준이라 화면 구조에 따라 엉뚱한 textarea(빈 값/다른 필드)에
  값을 넣고, 실제 URL 검색창은 비어있는 채로 검색 버튼만 눌리는 경우가
  있었음 → "검색결과 없음"의 원인으로 추정
- url_input()을 3단계 정밀 탐색으로 재작성:
  1) 버튼과 같은 <tr> 안에서 우선 탐색
  2) 상위 요소를 한 단계씩(최대 4단계) 올라가며 후보가 "정확히 1개"일 때만 채택
  3) 최후 수단: 페이지 전체에서 rows 속성이 가장 큰 textarea(URL 여러 줄
     입력용일 가능성 높음)
- 선택된 필드 정보(태그/name/id/rows)와 입력 직후 최종 값을 매 행마다 로그로 출력
  → 다음에 또 틀리면 원인을 바로 알 수 있도록 진단 강화
- type_into()에 keyup/blur 이벤트 디스패치 추가(구형 JS가 input/change만이
  아니라 keyup/blur를 볼 수도 있음), 입력값 불일치 시 경고 로그 출력
- 브라우저는 이미 CDP로 실제 Chrome/Edge 창(사용자가 보는 그 화면)에
  직접 연결해 조작 중임을 확인 — 별도 숨겨진 브라우저 아님
- 검증: 버튼과 URL입력칸이 서로 다른 tr/table에 있고 페이지에 관련없는
  textarea(메모/설명 등)가 여러 개 섞인 까다로운 mock 화면에서 정확한
  필드만 선택·입력하고 다른 필드는 건드리지 않음을 확인
